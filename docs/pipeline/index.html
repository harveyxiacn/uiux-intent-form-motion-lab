工序版 · 一份对这套 Skill 的理解 · 2026.10

「卡片删除时飞走，
别太夸张。」

原站把这句话交给生成器，匹配 141 条提示词里最像的一条。这里换一种读法：九个 Skill 不是九个工具，是一条流水线。同一句话依次经过意图、样子、令牌、行为、组件、动效、手持、证据、提示词九道工序，每道都留下一张别人能检查的交接单。旁边的手机原型会随工序一点点长出来，从头到尾都能真的删、真的撤销。

  1. 先任务，后样子。不知道谁在删、为什么删之前，不讨论飞走的角度。
  2. 业务状态和动画分开。动画被打断、被关掉、被跳过，数据都必须是对的。
  3. 证据大于声明。每道工序写明已验证什么，没验证的列进清单往下传。

流水线

滚动或点工序号，手机原型切换到这一工序的视角。每张交接单底部的已验证未验证是这页自己能证明和不能证明的范围。

    01

    uiux-page-planning

    意图：先看清谁在删

    “飞走”是结果，不是需求。先回答：这是 App 还是网页？删的人在什么情境？删错了怎么办？原型此刻只剩灰块和区域编号——还没到谈好不好看的时候。

    界面
    手机 App（单手、通勤间隙清理清单）事实
    主任务
    划掉已完成或记错的任务，不打断节奏
    区域顺序
    ① 今日进度 ② 任务列表 ③ 新建入口 ④ 底部导航
    必须的状态
    空清单 · 删除后可撤销 · 同步失败
    假设
    删除可撤销 5 秒，无需二次确认弹窗假设

    已验证原型包含空状态与撤销入口
    未验证真实用户是否需要二次确认

    02

    uiux-style-direction

    样子：把“别太夸张”翻成决定

    “别太夸张”不是形容词，是约束：动效要比内容安静。每一条方向都对应一个截图里看得见的东西。

    意图
    安静的纸面清单，内容先于装饰
    构图
    大号日期 + 进度条压在首屏，列表行高 56px 以上
    字
    系统黑体；数字用等宽，进度跳动时不抖
    颜色角色
    强调色只给“新建”；红色只出现在删除露出的那一条
    可见检查
    首屏截图里只有一处强调色；红色在静止画面中不出现

    已验证静止状态下没有红色元素
    未验证品牌方是否认可这套方向

    03

    uiux-design-system

    令牌：颜色有身份，不只是数值

    深色模式不是反色。下表的对比度是页面用 WCAG 公式实时计算的，切换主题后会重算。

    原型主题
    原型语义令牌与对比度
    角色值用在对比度

    已验证四组文字/底色组合在两种主题下计算值 ≥ 4.5:1
    未验证真机屏幕与色弱模拟

    04

    uiux-interaction-spec

    行为：五段式交互契约

    把“飞走”拆成别人可以照着实现、也可以照着验收的五段。点下面的按钮，在原型上逐段回放。

    1. 目的与对象移除一条任务；响应的是这一行。
    2. 触发左滑超过行宽 40% · 行尾“⋯”菜单 · 聚焦时按 Delete。三条路径结果相同。
    3. 过程行向左离开并轻微倾斜，随后下方行补位；撤销条从底部升起。
    4. 结果与反向数据立即标记删除；5 秒内可撤销，撤销后回到原位置；未过阈值松手则弹回。
    5. 无障碍与降级读屏播报“已删除，可撤销”；焦点移到下一行；减少动态效果时只淡出。

    已验证三条触发路径在原型中均可用
    未验证40% 阈值是否符合目标用户手感（提议值）

    05

    uiux-component-engineering

    组件：谁拥有状态

    列表拥有数据，行只拥有“拖到哪了”。把一行切到不同状态，看它是否每种都说得清楚。

    状态归属
    TaskList 持有 items 与 pendingUndo；TaskRow 只持有 dragX
    事件
    onRemove(id, via) · onUndo(id)
    焦点策略
    删除后 → 下一行 → 上一行 → 空状态标题，永不落到 body

    已验证删除后 document.activeElement 不是 body（页内自检）
    未验证异步失败的真实网络行为（这里是模拟）

    06

    uiux-motion-engineering

    动效：可以被打断

    右边的日志分两栏：数据在点击那一刻就变了，画面随后才追上。试试连续删、删一半撤销、开慢放。

    离场
    220ms · 倾斜 ≤ 3° · 无回弹提议
    补位
    180ms · ease-out提议
    中断
    撤销时动画原路反向，不重新开始
    减少动态
    无位移，120ms 淡出，状态与播报不变

    数据

      画面

        已验证连删、反向、减少动态三种路径无残留遮挡
        未验证低端机帧率（截图证明不了流畅）

        07

        uiux-mobile-patterns

        手持：拇指够得着吗

        原型叠上了安全区和拇指热区。撤销条必须在底部导航和 Home 指示条之上，滑动必须有看得见的替代。

        可达
        “⋯”和撤销都落在拇指舒适区
        安全区
        顶部状态栏、底部 34px 指示条不放可点元素
        手势替代
        “⋯” → 底部动作面板 → 删除；面板可 Esc / 点遮罩关闭，焦点回到“⋯”
        返回路径
        关闭面板保留滚动位置与筛选

        已验证390×844 视口下撤销条不被遮挡
        未验证真机、软键盘、系统返回手势

        08

        uiux-accessibility-review

        证据：修复前后对照

        切到“修复前”，原型会退回一个常见的初版：只有滑动、删完焦点丢失、没有播报、灰字太浅。每条发现都写明怎么复现、怎么复测。

          读屏会听到

          （还没有播报）

          已验证播报文本、焦点去向、计算对比度
          未验证NVDA / VoiceOver 实机朗读；这不是 WCAG 认证

          09

          uiux-prompt-playbook

          提示词：前八道的合订本

          原站的提示词是从库里“挑”出来的；这里的提示词是从前八张交接单“装订”出来的——每一行都能指回它来自哪道工序。

          看装订好的提示词 ↓

          已验证验收项全部可在本页原型上执行
          未验证交给其它 Agent 后的实现质量

            Skill 改动
            
      
            我对 Skill 做了什么
            
      
            原有九个模块各自写得清楚，但彼此之间没有“交接”的约定：README 写了“明确目标 → 视觉方向 → 交互动效 → 验收”，却没有一个 Skill 负责这条顺序。改动只补缺口，不重写原有内容。
            
    
            
    
              
      
            1. 新增 uiux-workflow路由 Skill：判断请求需要哪几道工序、从哪道开始、什么时候跳过；规定交接单区分事实/选择/假设，未验证项必须向下传。附 references/handoff-artifacts.md 九张交接单模板。
              2. 
      
            2. 九个模块各加「Handoff」段写明接收什么、交出什么、交给谁。原来每个 Skill 独立可用，现在也能串起来用，且不依赖安装 workflow。
              3. 
      
            3. 补两条示例验收uiux-page-planning 与 uiux-style-direction 原本是仅有的两个没有“Example acceptance”的模块。
              4. 
      
            4. 三处描述加反向触发page-planning / style-direction / interaction-spec 的 description 增加 “Not for …”，减少相邻 Skill 被误触发。
              5. 
    
            
    
            保留未动：三份重复的 surface-routing.md（安装脚本按目录复制，每个 Skill 需要自带一份）；提示词手册的 141 条数据与生成器（工作区里有未提交的改动，属于原作者）。
